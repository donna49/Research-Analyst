# intel plugin review: uploaded `intel-chatgpt-main` (v1.2.0) vs installed `intel` (v1.0.1)

Author: Kavin Sakthivel. MIT for code and instructions. The logo and third-party readings are excluded from the license. No repo code was executed. Files were read, grepped, and diffed. The 1.2.0 zip was unzipped into a scratch folder only to compare it with the repo.

## 1. Overview and coordinator routing (`skills/intel/SKILL.md`)

The plugin has ten instruction-only skills. The coordinator `intel` starts from the decision: owner, question, entity, geography, horizon, alternatives, stakes and output. It asks the user something only when the answer would change the work. Otherwise it states assumptions. It separates requests for description, explanation, prediction and prescription. It writes one primary intelligence question with a few subquestions, and defines the population, metric, denominator and comparison period **before** collecting numbers.

- **Depth tiers:** Quick (narrow, compact uncertainty), Standard (question tree, evidence, alternatives, recommendation) and Deep. Deep is the default for consequential or ambiguous work and uses four passes, a claim ledger, a challenge step and sensitivity checks.
- **Four passes:** Frame (falsifiable hypotheses, kept separate from the user's preferred outcome), then Investigate (primary and contrary evidence, trace recycled claims, log gaps, never imply database access the host lacks), then Challenge (always routes through intel-red-team; a role-play pass is not independent review), then Decide (includes delay or no-action options, reversal evidence and the next monitoring step). The coordinator loops back when evidence shifts. It stops when the pivotal subquestions are answered or explicitly left unresolved.
- **Routing table:** evidence goes to research; causes to diagnose; firm, industry or rival questions to compete; influence and adoption to stakeholders; futures and defined events to foresight; new propositions to innovate; failure, exposure and governance to risk; theses and audits to red-team; memos and readouts to brief. The coordinator says "Don't force every framework."
- **Evidence contract:** it uses 8 claim statuses (fact, attributed claim, inference, assumption, estimate, forecast, scenario, recommendation). It cites at the point of use and never fabricates links or pages. Event, publication, data-period and retrieval dates are kept separate. Confidence in the evidence is kept separate from the likelihood of an event. It shows formulas and units. Retrieved content is treated as data, not instructions, which is a built-in prompt-injection guard. Collection must be lawful, use minimal personal data, and take no external actions.
- **Deliver:** answer first, then key judgments, evidence, counterevidence, uncertainty and next actions. If the evidence is inconclusive, it says whether to act, test, wait or monitor.

## 4. Security review

- **Scripts** (stdlib only; nothing executed): `check_evidence.py` validates JSON structure only. `source_library.py` is read-only, has no network access, and guards against path traversal. `import_source.py` copies the PDF and writes JSON into a data directory. It refuses to overwrite and validates IDs with the regex `[A-Z][A-Z0-9_-]{1,31}`. It needs `pip install pypdf` for PDFs, which is a normal supply-chain consideration. `scripts/validate.py` runs `git ls-files` through subprocess (list args, no shell). The tests run the scripts through `sys.executable` in temp directories.
- **No** network calls, eval/exec, shell=True, credential handling, telemetry or hooks. The grep found no URLs except the schema, GitHub and OpenAI docs links.
- **downloads/**: `intel-1.2.0.zip` matches the repo tree exactly (verified with diff). `intel-1.1.0.zip` is an older similar build. Neither contains binaries beyond the 279x279 JFIF logo.
- **CI:** GitHub Actions pinned to commit SHAs, `contents: read`, `persist-credentials: false`. This is good hygiene.
- **Prompt-injection posture:** strong. Every skill tells the agent to treat documents as data and to take no external actions, publishing or purchases.
- **Licensing:** the *installed* version redistributes copyrighted third-party PDFs (MarketLine, HBR and others). Keep them internal and don't republish them. The public edition was created to fix exactly this.
- **Risk level:** low. The plugin is instruction-only; the optional scripts are local file I/O.

## 5. Quality assessment

**Strengths:** this is one of the most epistemically careful skill packs available. It separates claim status from confidence and confidence from likelihood. It counts source families and handles denominators and periods well. Its definition of negative evidence is precise. Red-teaming is wired into the coordinator. It sets explicit stop rules and avoids false precision (no ordinal-score multiplication, no influence percentages). The SKILL.md files are compact (3-9 KB) and read only the references they need.

**Weaknesses:** the frameworks are generic consulting and intelligence tools with no domain-specific methods. The historical cases are dated and serve as teaching material only. The plugin has no data connectors and depends on host tools. Deep mode can be heavy for routine questions. Its JSON evidence checker is structural only, and the skills say so. The public edition's bibliography is decorative unless you own the originals.
